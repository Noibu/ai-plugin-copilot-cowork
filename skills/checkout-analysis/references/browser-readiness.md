# Browser readiness — only when a browser step is needed

Analytics, imported evidence and report display do not require a browser connection. Do not interrupt those tasks with setup prompts. If the current browser is usable, continue without repeating setup.

When a requested browser-dependent step is blocked because this chat has no connected local browser, explain which step cannot run and provide this short user-controlled path:

1. Download/install Microsoft Edge if needed.
2. Open Copilot Cowork on the web in Edge; sign in to Edge and Cowork with the same work account.
3. Complete the browser connection and first-run consent through the host's own interface, if offered. Do not invent control names, setup URLs or a successful connection.
4. Organizational browsing must be enabled by the organization. If policy blocks it, explain that boundary; do not change or circumvent administrator policy or browser security settings.

Other browsers, desktop and mobile cannot run these local browser tasks. Ask only for the missing prerequisite when browser work is actually needed. Never ask for passwords, cookies, tokens, MFA codes or other secrets in chat. Use the host's native sign-in/consent flow. Resume the selected scope after actual readiness evidence; do not claim connection from a user's intention alone.

While blocked, continue available Noibu/nonbrowser analysis, imported-evidence processing and report preparation; mark site validation, live inspection or the requested browser step as not performed. Browser connection alone does not grant approved page-script execution for axe. Preserve that separate capability boundary.

Official reference: [Use Copilot Cowork with your local browser](https://learn.microsoft.com/en-us/microsoft-365/copilot/cowork/cowork-local-browser). This is a concise setup summary, not a new installation or policy mechanism.
