# Verified query results → report mapping (21.1.11)

For FULL checkout or segment reports, read this before writing report.json, including the fast Adaptive Card path. `build_presentation.py` runs `prepare_report` BEFORE validation/rendering in HTML, full Adaptive Card AND compact. Helpers do not query Noibu or prove coverage; populate them ONLY from verified current schemas and actual aggregate evidence, keeping raw results separately. Do not hand-build a two-row preview and claim five were fetched. Legacy explicit funnel/tables still work. Ambiguous dual representation is rejected: normalized segments accept only unrelated explicitly supporting legacy tables; normalized checkout rejects preexisting payment/delivery bar tables while allowing abandonment. Mapping removes normalized blocks from its returned copy so validate/normalize is idempotent; the original evidence file is unchanged.

## Explicit comparison scope — every workflow

Supply `comparison: {mode, label}`. Mode is `snapshot`, `previous-period`, `within-window` or `mixed`; label declares actual periods/cohorts/timezone and which metrics are compared. Snapshot mixes or channels must not inherit a prior-period footer from an unrelated device trend. A segment report may say “Current-window segment rankings; device ratio compares Oct 1–15 vs Oct 16–30 (UTC)”. Without metadata the footer truthfully says “Snapshot only; comparison scope not supplied”, never an invented “vs previous period”. Deltas still require measured comparator evidence. In-card scope replaces an external explanatory sentence.

## Checkout normalized method block

Retain `funnel` raw current/prior distinct session counts, ordered cart → checkout → payment → completed (null where unmeasured), with canonical labels or typed roles from [funnel presentation](funnel-visualization.md). Checkout geometry and later-stage headlines use calculated percentages of that SAME period's positive measured cart count, NOT counts or previous-stage conversion. First-stage headline stays the baseline COUNT; visible context declares 100%. Each period normalizes to its OWN cart baseline, preserving current/prior raw count fields. The mapper overrides stale `display`, rates and deltas, computes signed pp changes only for valid current/prior rates, and recomputes `funnelBasis` denominator/coverage metadata. Unknown/zero bases and unmeasured stages show Not measured with exact counts still available. Full AND compact include Show exact counts for ALL stages. Checkout completion remains a separate completed / started-checkout metric. Keep mobile/desktop/value highlights, observed abandonment rows (`placement: overview`), denominator/window/currency details and express-checkout caveats. A row sample is not a population loss total.

Optional `checkout: {mixes: {payment?, delivery?}, missing: [reason...]}` maps each verified populated dimension into a side-by-side overview bar table. Each mix has EXACT fields:

- `rows: [{label: <actual method>, count: <nonnegative integer>}, ...]` (≤50), sorted by count by the mapper; six are previewed, not five. Keep remaining evidence in the input/export.
- `population: "completed-orders"` ONLY with an actual completed-order grain/count and a completed-order filter. Prefer distinct completed order IDs or an exposed verified completed-order count. Do not equate `COUNT(session)` with orders.
- If order grain cannot be queried, use `population: "completed-purchasing-sessions"`; the card explicitly labels this lower-fidelity proxy “purchasing sessions (order grain unavailable)”. Never relabel it as order counts or infer failed gateway attempts from it.
- `coveredCount`, `completedCount`: distinct population members with a populated method versus the SAME completed-population denominator/window. Integers, covered ≤ completed; every method count ≤ covered. Nonoverlapping row counts must sum to AT MOST covered population. A lower sum is valid bounded category coverage and the mapper states returned-category coverage and bounded method roster; equality proves reconciliation only when complete categories were actually established. Reject impossible overcounts, not a valid partial roster. Array-join row sums are not this coverage measure.
- `overlap: true|false`: true when an order/session can name multiple methods; counts are then not additive. Deduplicate method membership within each population member before counting. Never claim 100% coverage from overlapping row sums.
- `currencyScope`: measured currency components and limitations, e.g. “CAD only; EUR reported separately”. Mix counts need not be split by currency when the count population spans currencies, but money/median values must not pool them.

Missing/unsupported/unpopulated methods go in `missing` with the exact schema/coverage reason. Do not fabricate bars. The checkout renderer always keeps supported abandonment AND BOTH available method tables, not the generic two-table limit. Full charts have standard count-scaled visual fallbacks; compact removes extensions but retains count-scaled tracks and both mixes. Six preview rows and missing/null are tested offline.

## Segment normalized aggregate block

`segments` has EXACT fields:

- `countries`, `channels`: complete returned aggregate rows `{label, sessions, purchasingSessions, revenuePerSession?}`. Counts are distinct cohort sessions and purchasing sessions (0 ≤ purchasers ≤ sessions). `revenuePerSession` is a measured currency-labelled display string or null. Do not use a screenshot as evidence. Preserve raw source/medium identity (no alias merging).
- `minSessions`: explicit positive threshold for BEST-CONVERTING ranking (e.g. 1000). Broad country/visited aggregates have no such threshold.
- `countryScope`, `channelScope`: `global-complete` only when the requested ranking is proven by complete pagination/aggregation or a complete server-side correctly ordered ranking query; otherwise `bounded`. Never promote an early sessions-ranked page to a global best-CVR list.
- `currencyScope`: measured per-currency treatment/limits; revenue/session components must not be pooled or silently converted.

The mapper sorts countries/regions by sessions, excludes unknown placeholders to a SEPARATE in-card coverage note and shows the top FIVE known regions (all if fewer, with an explicit eligible-row count). It produces all three tables when supported: Countries / regions, Best converting channels (minSessions+), Most visited channels. Each has Sessions, CVR (purchasing sessions / sessions) and Rev/session; best conversion applies the explicit volume filter BEFORE descending CVR sort; visited uses descending sessions. If one section is unavailable/no eligible rows, the card says which and why, not an invented substitute. Full AND compact retain all three sections × five eligible rows. Supporting history stays separate.

## Acquisition contract (no underfetch)

Check current Noibu session query schemas before selecting dimensions/aggregation/pagination; do not invent API fields. Fetch countries ordered sessions with enough pages to obtain five KNOWN regions after excluding unknown. For channels, use a separate verified aggregate query applying the minSessions filter BEFORE ordering CVR, plus a sessions-ordered visited query, or collect ALL channel aggregate pages and compute both rankings locally. A single limit30 ordered-sessions result cannot establish global top conversion. Deduplicate aggregate pages by exact dimension keys; do not sum duplicate pages or sum overlapping cohorts into site baseline. If pagination/aggregate filters are unsupported, label rankings bounded to the returned cohort and record coverage in the card. A row-level sample cannot establish population rankings. Keep the direct whole-domain control query and UTM/currency cautions.
